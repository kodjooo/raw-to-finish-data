Основное итоговое название (name_main) — обязательно нужно составить самостоятельно на основании неструктурированной информации, АНАЛОГИЧНО НАЗВАНИЯМ В ВЕКТОРНОЙ БАЗЕ (файл "main_and_minor_names.json").

name_main должно использовать ТОЛЬКО слова из «Основное изначальное название» от пользователя (такое же написание) + служебные добавки: тип напитка, объём, год, информация о подарочной упаковке, классификатор (из неструктурированной информации). Любые другие сущности (производитель, регион, оценки, награды, лозунги) НЕЛЬЗЯ добавлять в name_main, даже если они есть в неструктурированном описании.

Второстепенное итоговое название (name_minor) — аналогично, но строится ТОЛЬКО на основе «Второстепенное изначальное название» + служебные добавки: тип напитка, объём, год, информация о подарочной упаковке. КЛАССИФИКАТОР В name_minor СТРОГО ЗАПРЕЩЁН.

Обязательная последовательность внутри итоговых названий (по смыслу, до форматирования):
1) тип напитка ("Вино", "Вермут", "Портвейн", "Херес", "Винный напиток" или "Игристый винный напиток")
2) название товара (name_title_raw), извлечённое ТОЛЬКО из соответствующего исходного названия этой версии.
Если в исходном названии вместо названия указан сорт винограда — сорт берётся ТОЛЬКО из этого исходного названия (как написан там), без перевода/транслитерации и без подмены значением grape_varieties.
3) бренд
4) классификатор (если явно указан)
5) год (если указан)
6) объём в литрах (если указан)
7) информация о том, есть ли у товара подарочная упаковка (если указана)

В name_main и name_minor НЕЛЬЗЯ использовать кавычки вокруг частей названия.

ОТДЕЛЬНЫЕ ЖЁСТКИЕ ПРАВИЛА ПРО БРЕНД И ПРОИЗВОДИТЕЛЯ 
====================================================================

ТЕРМИНЫ
— brand_component = то, что будет стоять в позиции "бренд" внутри name_main/name_minor.
— brand_key (JSON-ключ brand) создаётся ТОЛЬКО при наличии маркера "Бренд" в блоке "Характеристики".

ИСТОЧНИКИ И ПРИОРИТЕТЫ
1) Если в блоке «Характеристики» есть маркер «Бренд», то:
   — brand_key в JSON создаётся и берётся только из поля «Бренд».
   — brand_component для name_main/name_minor = значение поля «Бренд» (в нужной языковой форме).

2) НОРМАЛИЗАЦИЯ ПОЛЯ «Бренд» (ОБЯЗАТЕЛЬНО):
— brand_key (значение JSON-ключа "brand") всегда ТОЛЬКО одно значение, не список и не перечисление.
— Если значение поля «Бренд» содержит несколько элементов, вернуть ТОЛЬКО первый элемент, остальные игнорировать.
— Перечисление брендов считается ТОЛЬКО если разделитель находится ВНЕ круглых скобок.
— Разделители, которые означают перечисление (ЕСЛИ они ВНЕ скобок): запятая, точка с запятой, "/", "|", "&", "+", а также слова " и " / "and".
— Скобки сохранять как часть бренда, если они находятся в первом элементе:
   "Fiorino d'Oro (Natale Verga)" → brand_key = "Fiorino d'Oro (Natale Verga)" (НЕ обрезать).
— Техническое правило:
   1) Просканируй строку «Бренд» слева направо.
   2) Игнорируй любые разделители, пока ты внутри "( ... )".
   3) Как только встретился первый разделитель ВНЕ скобок — обрежь строку по нему (слева).
   4) Подчисти пробелы и запятые по краям результата.
— Запрещено возвращать "brand": "Martini, Bianco" или "brand": "X, Y". Должно быть только "brand": "Martini" (первый элемент).
— Это правило влияет и на поиск brand_component в исходных названиях: искать нужно уже нормализованный brand_key (первый элемент).

3) Если маркера «Бренд» НЕТ вообще, то:
   — brand_key в JSON НЕ создаётся (запрещено создавать ключ brand).
   — brand_component для name_main/name_minor = PRODUCER_FALLBACK, извлечённый из исходных названий (см. ниже).
   — producer (JSON-ключ producer) заполняется по обычным правилам (если найден).

PRODUCER_FALLBACK (обязательная логика, если «Бренд» отсутствует)
1) Если после удаления типа напитка ("Вино", "Вермут" и т.п.) в соответствующем исходном названии СРАЗУ идут кавычки
("...", «...», ‘…’), то producer_fallback = содержимое ПЕРВОЙ пары кавычек (как написано).
Пример: Вино "Дербентский" Кагор → producer_fallback = Дербентский
Пример: Вермут "Martini" Bianco → producer_fallback = Martini
Примечание: кавычки из producer_fallback удаляются (остаётся только текст внутри), но само значение НЕ теряется.
2) Сначала извлеки producer_fallback_main из «Основного изначального названия»:
   — это фрагмент, который явно выглядит как имя производителя и стоит в начале названия
     (обычно до первой запятой или до кавычек/скобок), например:
     "Luis Felipe Edwards (LFE)", "Myskhako", "Tiflis Wine Cellar", "Мысхако" и т.п.
3) Затем извлеки producer_fallback_minor из «Второстепенного изначального названия» тем же правилом.
4) В name_main используй producer_fallback_main, в name_minor — producer_fallback_minor.
5) Запрещено переводить/транслитерировать producer_fallback: используется ТОЛЬКО как встретилось в соответствующем исходном названии.
6) Если в каком-то из исходных названий producer_fallback не извлекается однозначно, то для этой версии brand_component пропускается (т.е. имя строится без блока бренда/производителя).

ЗАПРЕТ НА ПОДМЕНУ
— Если маркер «Бренд» есть: producer НИКОГДА не используется в позиции бренда.
— Если маркера «Бренд» нет: в позиции бренда используется ТОЛЬКО producer_fallback из исходных названий (а не producer из характеристик и не что-то из описания/векторной базы).

ОЧИСТКА НАЗВАНИЯ ТОВАРА (name_title_raw)
====================================================================

Перед формированием name_main и name_minor ты обязан сначала получить «чистое название товара» (name_title_raw) отдельно для основного и второстепенного названия.

Для каждого исходного названия выполняй такие шаги:
0. ДО очистки извлеки brand_component для этой версии:
   — если есть маркер «Бренд» → brand_component определяется по блоку «ЯЗЫКОВАЯ ФОРМА БРЕНДА ДЛЯ ИМЕНИ» (включая вариант бренда из кавычек/начала соответствующего исходного названия).
   — если маркера «Бренд» нет → brand_component = producer_fallback из этого исходного названия (см. блок выше).

1. Возьми исходное название и УДАЛИ из него:
   – тип напитка ("Вино", "Виски", "Коньяк" и т.п.), а также их английские аналоги ("Wine", "Whisky" и т.п.), если они явно обозначают только тип;
   – объём, год, упаковку (всё вроде "0.75 л", "0,75 л", "750 мл", "2020", "2023", "(п/у)", "подарочная упаковка");
   – служебные слова вида "wine", "vino", "vin", если они явно обозначают только тип напитка, а не часть имени.

2. Удали все вхождения brand_component и producer (как сущностей), чтобы они не дублировались в "Название товара":
   – brand_component удаляется всегда (если он определён);
   – producer удаляется всегда (в любом виде), даже если brand_component = producer_fallback.

2.2. После удаления типа напитка, объёма, годов и кавычек ты обязан многократно проверить и удалить из name_title_raw все вхождения бренда и производителя (и их простых вариаций) как отдельных слов:
на русском и английском;
в транслитерации (Myskhako / Мысхако, Black Out / Блэк Аут и т.п.);
с возможными пробелами и дефисами внутри.
Удаление выполняется циклом «пока в name_title_raw ещё есть такие вхождения — удаляй их целиком вместе с лишними пробелами и запятыми вокруг».
Пример:
Исходное название: Вино Myskhako, "Black Out" Merlot
Бренд: Black Out
Производитель: Мысхако
После очистки (пункты 1–2.2) name_title_raw ДОЛЖЕН быть строго: Merlot.
Аналогично второстепенному названию Мысхако, "Блэк Аут" Мерло, 750 мл — после очистки name_title_raw ДОЛЖЕН быть: Мерло.

3. При очистке исходного названия ОБЯЗАТЕЛЬНО удали из него любую информацию о крепости:
   – все фрагменты, где есть знак "%", например "11 %", "13.5 %", "14,7 %".
   Эти элементы НЕ МОГУТ входить в "Название товара" и не могут попадать в name_main или name_minor. Крепость допустима только в поле "alcohol_percent".

4. Любые кавычки вокруг частей имени ( `"..."`, `«...»`, `‘…’` ) нужно удалить ещё на этапе очистки. Внутри name_title_raw, name_main и name_minor кавычек быть не должно вообще.

5. Удали из name_title_raw любые элементы, которые явно относятся не к имени, а к другим полям:
   – значения крепости, проценты;
   – чистые классификаторы (DOC, DOCG, AOC и т.п.) — они должны идти в отдельное поле «классификатор» и свою позицию в итоговом имени, но НЕ оставаться в середине «Название товара».

6. После всех удалений подчисти строку:
   – убери двойные пробелы;
   – убери пробелы и запятые в начале/конце строки;
   – если строка начинается или заканчивается запятой — убери её.

7. Примеры ожидаемого результата:
   – «Вино "Картули Вази" Ахашени» → name_title_raw ДОЛЖЕН быть "Ахашени";
   – «Вино "Уроки Французского" Каберне Фран» → name_title_raw ДОЛЖЕН быть "Каберне Фран";
   – «Вино Myskhako "Quintessence" Zinfandel» → name_title_raw ДОЛЖЕН быть "Quintessence Zinfandel";
   – «Вино "Инкерман" Рислинг Вайнмейкер'с Селекшн» → name_title_raw ДОЛЖЕН быть "Рислинг Вайнмейкер'с Селекшн";
   – «GreenLife Sauvignon Blanc Blush» → name_title_raw ДОЛЖЕН быть "Sauvignon Blanc Blush".

8. Если после удаления бренда и производителя строка стала пустой (например, название было почти целиком брендом), тогда:
   – в качестве name_title_raw можно использовать стиль, ЕСЛИ он явно указан в этом же названии и ясно относится к имени (например, "Ахашени", "Kindzmarauli");
   – если такого явного элемента нет — считаем, что у товара нет собственного имени, и итоговое имя может строиться как "Вино {Бренд}, …" без блока «Название товара».

   СТИЛЬ КАК ЧАСТЬ ИМЕНИ (ОБЯЗАТЕЛЬНО):
   — Если в исходном названии данной версии (основной или второстепенной) явно присутствует стилевое имя вида
   "Красное Сухое", "Белое Сухое", "Красное Полусладкое", "Rosso Secco", "Bianco Dolce" и т.п.,
   то это стилевое имя допускается как name_title_raw.
   — Если после всех шагов очистки name_title_raw стал пустым или почти пустым (остались только запятые/пробелы),
   то установи name_title_raw = стилевое имя, В ТОЙ ЖЕ ФОРМЕ И ЯЗЫКЕ, как в соответствующем исходном названии.
   — Запрещено переводить/транслитерировать стилевое имя между версиями. В каждой версии сохраняй ровно то, что написано в её исходном названии.
   Пример:
   Основное исходное: "Rosso Secco" … → name_title_raw_main может быть "Rosso Secco"
   Второстепенное исходное: "Красное Сухое" … → name_title_raw_minor должно быть "Красное Сухое"

8.1. Если после всех шагов очистки name_title_raw полностью совпадает с брендом (с учётом регистра, но без кавычек), то:
считаем, что это название вина совпадает с брендом (как в случае Лыхны);
в name_title_raw оставляем это слово;
в итоговых строках name_main и name_minor отдельный блок бренда НЕ добавляем, чтобы не получать конструкции типа Лыхны, Лыхны.
При этом поле "brand" в JSON обязательно заполняется и содержит бренд, но внутри текстового имени бренд присутствует только один раз — в позиции названия товара.
Пример:
Основное название: Вино Вина и Воды Абхазии, "Лыхны"
Бренд: Лыхны
→ name_title_raw = Лыхны
→ name_main = Вино Лыхны, 0.75 л
→ brand = Лыхны.

9. Если после очистки name_title_raw всё ещё начинается или заканчивается строкой, совпадающей с брендом или производителем (даже с отличиями в регистре или простейшей транслитерации), ты обязан удалить эту часть из name_title_raw.

10. При очистке основной версии удаляй из name_title_raw именно brand_component_main.
При очистке второстепенной версии удаляй из name_title_raw именно brand_component_minor.

====================================================================
ЯЗЫКОВАЯ ФОРМА БРЕНДА ДЛЯ ИМЕНИ (ОБЯЗАТЕЛЬНО)
====================================================================

Разделяй:
— brand_key = значение ключа "brand" в JSON.
— brand_component = то, что вставляется в name_main/name_minor в позиции бренда.

ПРАВИЛО ИСТИНЫ
1) brand_key (JSON-ключ "brand") создаётся ТОЛЬКО если в тексте есть маркер "Бренд" в блоке "Характеристики".
2) brand_key берётся только из поля "Бренд" (как написано в характеристиках). Никакие названия не могут заменить brand_key.

ПРАВИЛО ЯЗЫКОВОЙ ФОРМЫ ДЛЯ ИМЕНИ
3) Если маркер "Бренд" есть, то brand_component для КАЖДОЙ версии имени выбирается так:
   3.1) Для name_main: сначала попытайся найти в «Основном изначальном названии» точное вхождение бренда в той форме, в которой оно встречается в этом названии (латиница/кириллица, регистр, пробелы/дефисы).
        Если найдено — brand_component_main = найденная форма из основного названия.
        Если НЕ найдено — brand_component_main = brand_key (из характеристик).
   3.2) Для name_minor: сначала попытайся найти в «Второстепенном изначальном названии» форму бренда.
     Сначала ищи точное вхождение brand_key.
     Если точного вхождения НЕТ, но во «Второстепенном изначальном названии» есть фрагмент бренда в кавычках (например "Uroki Francuzskogo") или в начале названия до первой запятой — используй ЭТОТ фрагмент как brand_component_minor.
     Это не считается переводом/транслитерацией, потому что берётся только из исходного названия как есть.
     Если и так определить нельзя — тогда brand_component_minor = brand_key.

4) Запрещено переводить/транслитерировать бренд, чтобы “получить вторую языковую форму”.
   Разрешено использовать альтернативную форму ТОЛЬКО если она реально написана в соответствующем исходном названии.

5) Если в исходных названиях встречаются обе формы (RU и EN), то каждая используется только в своей строке:
   — name_main использует форму из Основного названия;
   — name_minor использует форму из Второстепенного названия.

====================================================================
СТРОГИЙ ШАБЛОН ФОРМАТИРОВАНИЯ ИТОГОВЫХ НАЗВАНИЙ
====================================================================

Итоговые названия name_main и name_minor формируются строго по шаблону:
name_main формируется по шаблону:
{Тип напитка} {Название товара}, {Бренд}, {Классификатор}, {Год}, {Объём} {(п/у)}
name_minor формируется по шаблону (БЕЗ классификатора):
{Тип напитка} {Название товара}, {Бренд}, {Год}, {Объём} {(п/у)}

(аналогично для других типов — "Виски {…}", "Коньяк {…}" и т.п.)

Где:
– {Тип напитка} = всегда с заглавной буквы:
  "Вино", "Вермут", "Портвейн", "Херес", "Винный напиток", "Игристый винный напиток".
– {Название товара} = очищенный name_title_raw (после всех шагов из блока «Очистка названия товара»);
– {Бренд} = brand_component (для соответствующей версии имени), см. правила выше;
– {Классификатор} = одно значение из "wine_classifiers.json", если оно явно указано;
– {Год} = год урожая, если он явно указан;
– {Объём} = итоговая строка формата "0.75 л" и т.п.;
– (п/у) = добавляется только если явно указана подарочная упаковка.

Требования к шаблону:
1. Все элементы разделяются запятой и пробелом: ", ".
2. Порядок элементов НЕЛЬЗЯ менять.
3. Нельзя убирать или добавлять запятые сверх этого шаблона.
4. Название товара идёт единым блоком, без разрыва и без перемещения частей.
5. Бренд стоит строго ПОСЛЕ названия товара и никогда не дублируется внутри самого названия товара, кроме специального случая из пункта 8.1, когда name_title_raw полностью совпадает с брендом. В этом специальном случае бренд в массив компонентов не добавляется отдельным элементом и присутствует только внутри name_title_raw.
6. В name_main используется name_title_raw и подходящая форма бренда для основного исходного названия.
7. В name_minor используется свой name_title_raw и подходящая форма бренда для второстепенного исходного названия.
8. Запрещено переводить, транслитерировать или произвольно менять написание названия или бренда, если нужная форма не встречается в исходных названиях и не следует однозначно из поля «Бренд».
9. Если в исходных названиях есть разные языковые версии — каждая используется только в своём названии (name_main опирается на «Основное изначальное название», name_minor — на «Второстепенное изначальное название»).

Перед тем как собирать name_main / name_minor по шаблону, сделай дополнительную проверку:
Если в name_title_raw всё ещё встречается подстрока, совпадающая с брендом (любой языковой формы этого бренда) как отдельное слово, ты обязан удалить эту часть из name_title_raw и ещё раз подчистить пробелы и запятые.
Если после такого удаления name_title_raw становится пустым:
если у товара нет другого явного имени (стиль и т.п.), итоговое название строится как Вино {Бренд}, {…}, то есть бренд будет стоять только один раз и только в позиции бренда;
если же name_title_raw полностью совпадал с брендом (кейс из пункта 8.1), применяется логика из 8.1: бренд остаётся в name_title_raw, а отдельный блок бренда в строке имени не добавляется.
Пример:
Исходные названия:
– Вино Myskhako, "Black Out" Merlot
– Мысхако, "Блэк Аут" Мерло, 750 мл
Бренд: Black Out
Производитель: Мысхако
После очистки:
– name_title_raw_main = Merlot
– name_title_raw_minor = Мерло
Для основной версии (EN) бренд = Black Out;
Для второстепенной (RU) бренд = Блэк Аут (по форме из исходного названия).
Итог:
– name_main = Вино Merlot, Black Out, 0.75 л
– name_minor = Вино Мерло, Блэк Аут, 0.75 л.

Если в исходных названиях встречается значение, совпадающее с producer, оно всегда удаляется из name_title_raw (в обеих версиях) даже если бренд отсутствует.

ЖЁСТКОЕ ПРАВИЛО ПРО ЗАПЯТЫЕ
	•	Запрещено, чтобы итоговое название начиналось с Вино, / Виски, / Коньяк,.
	•	Если после очистки name_title_raw пустой, то итоговое имя строится БЕЗ блока названия товара и БЕЗ “лишней запятой”:
	•	корректно: Вино {Бренд}, {Классификатор}, {Год}, {Объём} {(п/у)}
	•	некорректно: Вино, {Бренд}, ...
	•	Техническое правило сборки: запятая ставится только между непустыми компонентами, то есть соединение делается по списку уже очищенных от пустых значений компонентов (кроме типа; тип всегда есть).
	•	Если name_main или name_minor содержит подстроку "Вино," (или "Виски,", "Коньяк,") — это ошибка. Нужно пересобрать строку без пустого блока “Название товара”.

АЛГОРИТМ ПОСТРОЕНИЯ name_main И name_minor (ФИНАЛЬНЫЙ)
====================================================================

Для name_main:

1) Определи тип напитка и запиши его в переменную type_capitalized.
   type_capitalized ВСЕГДА начинается с заглавной буквы и равен одному из:
   "Вино", "Вермут", "Портвейн", "Херес", "Винный напиток", "Игристый винный напиток".
2) Определи brand_component_main по правилам (бренд-маркер → языковая форма из основного названия; нет маркера → producer_fallback_main).
3) Построй name_title_raw для основного названия, удаляя brand_component_main и producer.
4) Выдели классификатор, год, объём и "(п/у)".
5) Собери компоненты: [type_capitalized, name_title_raw, brand_component_main, Классификатор, Год, Объём, "(п/у)"].
6) Удали пустые элементы (кроме типа) и склей ", ".

Для name_minor:

1) Определи тип напитка и запиши его в переменную type_capitalized.
   type_capitalized ВСЕГДА начинается с заглавной буквы и равен одному из:
   "Вино", "Вермут", "Портвейн", "Херес", "Винный напиток", "Игристый винный напиток".
2) Определи brand_component для второстепенной версии по блоку «ЯЗЫКОВАЯ ФОРМА БРЕНДА ДЛЯ ИМЕНИ».
3) Построй name_title_raw по шагам из блока «Очистка названия товара» для второстепенного исходного названия.
4) Выдели год, объём и "(п/у)", если они явно есть.
5) Собери компоненты в массив в строго таком порядке (ВАЖНО: без классификатора):
   [type_capitalized, name_title_raw (может быть пустым), brand_component (может отсутствовать), Год, Объём, "(п/у)"].
6) Удали из массива пустые элементы (кроме типа).
7) Соедини элементы массива строкой ", ". Это и есть name_minor.

ПЕРЕД ВОЗВРАТОМ ОТВЕТА ОБЯЗАТЕЛЬНО ПРОВЕРЬ:

– В name_main и name_minor бренд появляется только ОДИН раз: либо как отдельный элемент на позиции бренда, либо (в спецкейсе пункта 8.1) только внутри блока «Название товара», но никогда не дублируется и не встречается дважды в одной строке.
– Внутри блока «Название товара» нет бренда, производителя и значений крепости.
– В этих строках НЕТ символа "%". Если есть — это ошибка, крепость нужно убрать из имени.
– В этих строках НЕТ кавычек (", ', «, »). Если есть — их нужно удалить и переформулировать название без кавычек.
– Порядок компонент соответствует шаблону.
— Если brand_component определён как producer_fallback (когда «Бренд» отсутствует), ключ "brand" в JSON всё равно НЕ создаётся.
